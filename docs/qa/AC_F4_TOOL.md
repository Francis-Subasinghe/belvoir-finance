# Acceptance criteria: F4 cash-versus-profit explorer

**Task:** F4 in `TASKS.md`: "Build the cash-versus-profit explorer, with pure calculation logic, unit tests, and keyboard and screen-reader support", plus S3: "Write the explorer's calculation test table, covering blank, invalid and extreme inputs" (S3 is in this doc). F4 turns the F3 static shell at `/tools/cash-vs-profit/` (F3-10) into the one interactive tool in the PRD: "illustrative only, collects no data, and handles blank, invalid and extreme inputs". It also folds in the two V1 notes deferred from PR #29 (chart label size, and the missing icon on the topic-page tools card) and the CF-06 content rule carried forward from F3.
**Verifier:** Sentinel. **Also checked by:** Atlas (calculation model, defaults, copy and design fit; D-1 to D-12 and Q-1 to Q-10, decided), Aegis (CSP, hydration and the no-data rules, F4-25 to F4-34; Q-9, decided), Launchpad (Lighthouse and visual-regression gates, F4-45 to F4-50 and F4-55 to F4-57).
**Status:** Draft v0.3 (9 Oct 2026). v0.3 records Aegis's Lighthouse SEO exception (confirmed by Atlas) and the `SITE_CSP` rename. v0.2 (8 Oct 2026): v0.1 was written on `main` at `5fdc80e` (PR #29, the V1 visual layer, merged). v0.2 records Atlas's decisions on PR #30 (`99215e7`): Q-1 to Q-8 and Q-10, and D-1 to D-12, are **decided** as proposed, and Aegis's decision on Q-9 (confirmed by Atlas). It also records Atlas's acceptance of Forge's F4 amendments on PR #31, including the widened F4-56 baseline set. Follows `PRD.md`, `TASKS.md`, `ADR-0001-platform.md` (islands, logic in pure TypeScript modules, strict CSP with no inline scripts), `CONTENT_MODEL.md` (Tool), `OPEN_DECISIONS.md` (D6 no analytics, D10 illustrative only), `TEST_STRATEGY.md`, `AC_F1_SCAFFOLD.md`, `AC_F2_DESIGN_SYSTEM.md`, `AC_F3_PAGES.md`, `AC_V1_VISUAL.md` and `AGENTS.md`.

Each criterion has a check type and the evidence that goes in the PR:

- **Unit:** Vitest, merge-blocking in CI. Evidence: the test name and the CI run link.
- **Build:** an assertion on `dist/` (or on a fixture build) in `tests/build/`, merge-blocking in CI. Evidence: the test name and the CI run link.
- **E2E:** Playwright plus `@axe-core/playwright` at 360, 768 and 1280 px against the built site (and the gallery test build, F2-01), merge-blocking in CI. Evidence: the test name and the CI run link.
- **CI (Lighthouse) / E2E (blocking visual):** the blocking `Lighthouse` and `Visual regression` jobs. Evidence: the run link and summary.
- **Manual:** recorded in the PR with the commit tested, browser and viewport, plus screenshots where stated.

Every automated check that guards a rule has a **negative fixture** that must fail **the real check** (the same exported function, scan or build step CI runs), so a check that matches nothing can't pass vacuously (`AGENTS.md` rule 7). Fixtures live under `tests/fixtures/f4/` (content fixtures under the existing `tests/fixtures/content/negative/`) and never in `src/` or `content/`, so they can't reach `dist/`. Every test name starts with its F4 ID (for example `F4-09 P-15 blank sales is an error, not £0`). Criteria shaped by a decision cite it as **(decided, D-n)** or **(decided, Q-n)**.

## What the code does today (`5fdc80e`)

- **Tool page.** `src/pages/tools/[slug].astro` renders an eyebrow with the `cash-vs-profit` icon, the h1, the summary, a `StatusNotice` "Illustrative only" (`data-testid="illustrative-only"`), the Assumptions `<dl>` and Limitations. It has no control and no script; F3-10's test asserts `<(input|select|textarea|button|form)` doesn't match.
- **Content.** `content/tools/cash-vs-profit.yaml` has `usesOfficialValues: false`, `demo: true`, and one placeholder assumption ("Customer payment terms", default "30 days", "final values are set in F4"). Its summary says "(built in F4)". `toolSchema` (`src/content/schemas.ts`) has `assumptions[]` of `{ label, default, explanation }` (all strings), `reviewer` and `sourceRecord` as `optionalRef`, `usesOfficialValues: z.boolean().default(false)`, and **no CF-06 rule**. `AC_F3_PAGES.md` carries CF-06 forward to F4.
- **Form controls.** `src/components/forms/TextField.astro` (F2-27) links its label, hint and error, sets `aria-invalid` and prefixes "Error:". The error `<p>` only exists when `error` is passed at build time. `StatusNotice` supports `live` (`role="status"`).
- **No JavaScript anywhere.** `tests/build/f3-dist.test.ts` "F3-38 dist has no .js file and no script other than JSON-LD" and `tests/build/v1-dist.test.ts` "V1-45 / F3-38" enforce it.
