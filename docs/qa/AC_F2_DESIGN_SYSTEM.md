# Acceptance criteria: F2 design system

**Task:** F2 in `TASKS.md`: build the design system, meaning the story card, article header, source note, fact/estimate/example/opinion callouts, chart wrapper, form controls, status notice, navigation and footer. It also delivers the D12 low-fidelity wireframes (`OPEN_DECISIONS.md`).
**Verifier:** Sentinel. **Also checked by:** Atlas (design fit, D12 wireframes, F2-02 and F2-38; ADR-0002), Aegis (CSP and rendering, F2-33 to F2-35).
**Status:** Draft v0.2 (Atlas's decisions on PR #4 applied; see Decisions). Builds on the F1 scaffold (`feat/scaffold`, PR #3): `src/styles/tokens.css`, `src/styles/global.css`, `src/lib/contrast.ts`, `docs/design/CONTRAST.md` and `tests/unit/design-tokens.test.ts`. Follows `TASKS.md` (F1 gold rule, F2 scope), `TEST_STRATEGY.md` (gold rule under accessibility thresholds, breakpoints, WCAG 2.2 AA thresholds, budgets), `ADR-0001-platform.md` (security requirement 2, strict CSP only; it has no brand or colour rules) and `AC_F1_SCAFFOLD.md`.

Each criterion has a check type and the evidence that goes in the PR:

- **Unit:** Vitest, merge-blocking in CI. Evidence: the test name and the CI run link.
- **Build:** an assertion on `dist/` in `tests/build/`, merge-blocking in CI. Evidence: the test name and the CI run link.
- **E2E:** Playwright plus `@axe-core/playwright` at 360, 768 and 1280 px, against the built site and, for the gallery, the gallery test build (F2-01), merge-blocking in CI. Evidence: the test name and the CI run link.
- **Manual:** recorded in the PR with the commit tested, browser and viewport, plus screenshots where stated.

Every automated check that guards a rule also has a **negative fixture** that must fail, so a scanner that matches nothing can't pass vacuously (`AGENTS.md` rule 7).

## Decisions (Atlas, PR #4, 3 Oct 2026)

These were open in v0.1 and are now decided. The ACs below reflect them.

- **Gallery is dev and tests only.** It is kept out of `dist/` the same way Keystatic is (an opt-in flag, never set by `npm run build`), so F1-02's exact page list doesn't change (F2-01, F2-40).
- **D12 wireframes** cover the 7 sitemap pages (Home, Explore, Topic, Story, Tools directory, tool page, Source library) under `docs/design/wireframes/` (F2-02).
- **Status notice variants** are info, success, warning and error (F2-28).
- **Not-advice notice and demo banner** get a restyle only in F2. Their wording and behaviour (per-page `noindex`, when the banner shows) stay in F10 (F2-29).
- **Visual baselines** are report only until F2 is approved. Launchpad then makes them blocking, generated in the CI Linux image (F2-38).
- **Lighthouse CI** is a separate Launchpad task: report only at first, and merge-blocking before F3 merges. For F2, Sentinel runs Lighthouse locally and attaches the scores (F2-41).
- **Gold rule source:** `TASKS.md` F1 and `TEST_STRATEGY.md`. Atlas writes ADR-0002 (brand colours and the gold rule) alongside the F2 build (see the Gold rule section).

## Gold rule (`TASKS.md` F1 and `TEST_STRATEGY.md` accessibility thresholds; Atlas asked for this specifically)

**Source:** this rule comes from `TASKS.md` F1 and the accessibility thresholds in `TEST_STRATEGY.md`, not ADR-0001, which is the platform ADR. Atlas will write ADR-0002 (brand colours and the gold rule) alongside the F2 build. Once it lands, this section's reference moves to ADR-0002. Adding ADR-0002 is an F2 evidence item.

Brand gold `#C5A059` is used **only on navy `#0B132B` (7.48:1) or slate `#1C2541` (6.15:1)**. Gold text or UI on light surfaces uses `#7E6026` (`--color-gold-on-light`: 5.85:1 on white, 5.59:1 on alabaster, 5.52:1 on the notice background). The reverse also holds: `#7E6026` on slate measures 2.58:1, so it is never used on a dark surface.
