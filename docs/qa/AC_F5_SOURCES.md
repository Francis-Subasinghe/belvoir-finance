# Acceptance criteria: F5 source registry and feed intake (with L4)

**Task:** F5 in `TASKS.md`: "Seed the source registry with about 10 verified entries (aiming for about 50 over time). Build the intake parser module with hardening tests." Plus L4: "Add the scheduled feed-intake workflow skeleton, triggered manually first, with least-privilege permissions." Both ship against this one doc (L4 is F5-36 to F5-41). It also takes the F1-08 gaps carried to F5 (CF-07 to CF-09 in `AC_F2_DESIGN_SYSTEM.md`, and two unnumbered ones listed under "Carried forward").
**Verifier:** Sentinel (behaviour and failure modes). **Also checked by:** Aegis (every hardening AC, F5-12 to F5-41, binding; Q-4 to Q-8, Q-19 and Q-20), Atlas (registry seed, content-model changes, Q-1 to Q-3 and Q-9 to Q-18; Francis approves the seed under D7 and D9), Launchpad (the L4 workflow, F5-36 to F5-41, and the CI, Lighthouse and visual gates, F5-43 and F5-44).
**Status:** Draft v0.2 (9 Oct 2026). v0.1 was written on `main` at `1fae58a` (PR #31, the F4 explorer, merged), as PR #33. v0.2 folds in the room's decisions: Aegis on Q-4 to Q-8, Q-19 and Q-20 (with additions), and Atlas on Q-3 and Q-9 to Q-18. Q-1 and Q-2 are deferred to Francis's pre-launch list, with an interim rule enforced here. Decisions D-1 to D-12 restate what `ADR-0001-platform.md`, `CONTENT_MODEL.md`, the CF items and Aegis's binding intake rules (9 Oct 2026) decide. Aegis's rules stand in for the A1 threat model. Follows `PRD.md`, `TASKS.md`, `ADR-0001-platform.md` (Feed intake; security requirements 1, 6 and 7), `CONTENT_MODEL.md` (Source, SourceItem, Feed intake failure modes), `OPEN_DECISIONS.md` (D7, D8, D9), `TEST_STRATEGY.md`, `AC_F1_SCAFFOLD.md` (F1-08), `AC_F2_DESIGN_SYSTEM.md`, `AC_F3_PAGES.md`, `AC_V1_VISUAL.md`, `AC_F4_TOOL.md` and `AGENTS.md` (rules 2, 3, 7, 8).

Each criterion has a check type and the evidence that goes in the PR:

- **Unit:** Vitest, merge-blocking in CI. Evidence: the test name and the CI run link.
- **Build:** an assertion on `dist/` (or a fixture build) in `tests/build/`, merge-blocking in CI. Evidence: the test name and the CI run link.
- **E2E:** Playwright plus `@axe-core/playwright` at 360, 768 and 1280 px against the built site. Evidence: the test name and the CI run link.
- **Workflow:** a unit test that reads `.github/workflows/intake.yml` as YAML and asserts on it (the `tests/unit/repo-guards.test.ts` pattern). Evidence: the test name.
- **CI (Lighthouse) / E2E (blocking visual):** the blocking `Lighthouse` and `Visual regression` jobs. Evidence: the run link and summary.
- **Manual:** recorded in the PR with the commit tested.

Every automated check that guards a rule has a **negative fixture** that must fail **the real check** (the same exported function, scan or step CI runs), so a check that matches nothing can't pass vacuously (`AGENTS.md` rule 7). Feed fixtures live under `tests/fixtures/f5/feeds/`, network fixtures (scripted DNS answers and HTTP responses for an injected resolver and transport) under `tests/fixtures/f5/net/`, workflow fixtures under `tests/fixtures/f5/workflows/`, and content fixtures under `tests/fixtures/content/negative/`. None live in `src/` or `content/`. **No test touches the network:** every fetch test runs through the injected resolver and transport, and CI never reaches a real feed (D-11). Every test name starts with its F5 ID (for example `F5-13 X-09 billion laughs is rejected before expansion`). Criteria shaped by a question cite it as **(decided, Q-n)**, or **(deferred, Q-n)** for the two on Francis's list.

## What the code does today (`1fae58a`)

- **Schemas** (`src/content/schemas.ts`). `sourceSchema` is strict, with `httpsUrl` for `website` and an optional `feedUrl` (https, no username or password), `jurisdictionRule` (F3-22, F3-45) and the demo rules (F3-48: "(placeholder)" in the name, placeholder hosts via `isPlaceholderUrl`). It has no `lastError`, `lastErrorAt` or feedType/feedUrl rule. `sourceItemSchema` has `publishedAt` and `fetchedAt` as `z.coerce.date()` (the time and offset are lost; comment "left to F5 (CF-07)"), a `title` ≤ 300, an `excerpt` ≤ 500 with no rights rule (CF-09), and `sourceId` and `usedInStory` as plain slugs.
- **References** (`src/lib/content-rules.ts` `REFERENCES`). There are 11 reference types; SourceItem `sourceId` and `usedInStory` are **not checked**. The demo rules for stories, tools and charts say "until F5".
- **Keystatic.** `sourceItems` uses `fields.date` for both timestamps. `sources` has no error fields.
- **Content.** Two demo Sources (`example-official-statistics`, paused; `example-placeholder-research`, active, the only one on `/sources/`), both `feedType: none`. One demo SourceItem with date-only timestamps.
- **Guards.** F3-34 fails on any `gov.uk`, `hmrc` or `ons.gov` string in committed content (`tests/unit/f3-guards.test.ts`) and any such link in `dist/` (`tests/build/f3-dist.test.ts`). F3-11 checks that no SourceItem title or url reaches `dist/`.
- **No intake code, workflow or XML dependency in production.** `saxes` 6.0.0 is a devDependency used by Aegis's SVG check (`tests/helpers/svg-check.ts`). Workflows: `ci.yml` and `lighthouse.yml` only. The F1-32 guard already fails on `secrets.` or `pull_request_target` in any workflow.
- **Visual and Lighthouse.** `page-sources` (`/sources/`) is one of the 12 snapshot names (36 baselines). Lighthouse skips only `robots-txt` (F4-47).
