# Acceptance criteria: F3 pages and content rules

**Task:** F3 in `TASKS.md`: "Build the pages in the sitemap, with clearly marked demo content." That means every page in `SITEMAP_AND_JOURNEYS.md` (MVP list in `PRD.md`), built from the content collections, plus the content rules F2 carried forward to F3 (CF-01 to CF-05 in `AC_F2_DESIGN_SYSTEM.md`, from the F1-08 field-by-field diff).
**Verifier:** Sentinel. **Also checked by:** Atlas (page fit against the D12 wireframes, F3-05; content-model and sitemap changes, F3-29), Aegis (rendering safety and CSP, F3-38 and F3-39; the Source library field allowlist, F3-11; Contact, F3-13).
**Status:** Draft v0.2 (4 Oct 2026). v0.1 was written against `main` at `4387591` (F2 merged) and rebased onto `7b1cadd` as PR #17; v0.2 folds in Atlas's decisions on Q-1 to Q-17 (with Aegis on Q-3, Q-8 and Q-15), listed under Decisions. Follows `TASKS.md` (F3, line 14), `PRD.md` (MVP scope and quality bar), `SITEMAP_AND_JOURNEYS.md` (sitemap and Journey 1), `CONTENT_MODEL.md`, `ADR-0001-platform.md` (security requirements 0, 0b and 2), `ADR-0002-brand-colour-type.md`, `OPEN_DECISIONS.md` (D2, D4, D6, D8, D10, D12), `TEST_STRATEGY.md`, `AC_F1_SCAFFOLD.md`, `AC_F2_DESIGN_SYSTEM.md` and `AGENTS.md`. Criteria shaped by a decision cite it as **(decided, Q-n)**. Points where a decision meets another doc or AC are listed under Conflicts and follow-ups for Atlas.

Each criterion has a check type and the evidence that goes in the PR:

- **Unit:** Vitest, merge-blocking in CI. Evidence: the test name and the CI run link.
- **Build:** an assertion on `dist/` (or on a fixture build, see F3-31) in `tests/build/`, merge-blocking in CI. Evidence: the test name and the CI run link.
- **E2E:** Playwright plus `@axe-core/playwright` at 360, 768 and 1280 px against the built site, merge-blocking in CI. Evidence: the test name and the CI run link.
- **Manual:** recorded in the PR with the commit tested, browser and viewport, plus screenshots where stated.

Every automated check that guards a rule also has a **negative fixture** that must fail, so a check that matches nothing can't pass vacuously (`AGENTS.md` rule 7). Every test name starts with its F3 ID (for example `F3-15 dangling author fails`), so the PR status list maps straight to tests.

## What the code does today (baseline at `4387591`)

These facts set the starting point. Each one is a reason for an AC below.

- **References aren't checked.** Story `author`, `reviewer`, `sources[].source`, `pillars`, `topics`, `relatedStories` and `relatedTools`, Topic `readingPath` and `featuredTool`, and Source `owner` are plain slug strings in `src/content/schemas.ts`. `src/pages/stories/[slug].astro` falls back to the raw id when an entry is missing. Astro's own `reference()` wouldn't fix this alone: in Astro 7.3.5 it checks only the collection name, and `getEntry` just logs `Entry … was not found` as a warning (`node_modules/astro/dist/content/runtime.js`).
- **Duplicate ids only warn.** Astro's glob loader logs `DuplicateContentEntrySlugError` as a warning and keeps the last file, unless `prerenderConflictBehavior` is `"error"`. It also takes the id from a `slug` key in the data when one is present (`node_modules/astro/dist/content/loaders/glob.js`).
- **Dates are loosely coerced.** `z.coerce.date()` turns `2026-02-30` into 2 March 2026, `02/10/2026` into 10 February 2026 (US order), and `2026-10-03T00:30:00+01:00` into 2 October 2026 in UTC (checked on Node 24.21). `src/lib/format.ts` formats in UTC, which is right for date-only values.
- **`demo` defaults to `false` in Zod but `true` in Keystatic.** Keystatic's checkbox always writes its value, `false` included, and an empty Keystatic text field is left out of the file (checked against `@keystatic/core` 0.6.9). So a "demo is required, no default" rule doesn't stop editors saving non-demo stories.
- **No `factual`, `commercialInterest` or `jurisdictionNote` field exists**, so CF-02 and CF-05 need new fields. Topic, Tool and Person have no `demo` field, Person `placeholder` defaults to `false` in Zod and `true` in Keystatic, Story `pillars` and Topic `pillar` are free slugs, Source `jurisdiction` is a free string, and every Keystatic reference is a `fields.text` box.
- **The demo marker and per-page `noindex` already exist.** `BaseLayout.astro` emits `<meta name="belvoir-demo" content="true">` in `<head>` and `noindex, nofollow` when the page's entry has `demo: true`, and the story page renders `DemoBanner`. Lighthouse CI uses the marker to skip SEO on demo pages, and `404.html` has its own named SEO exception (PR #14).
- **Pages built today:** `index.html`, `stories/index.html`, `stories/why-profit-isnt-cash/index.html` and `404.html`. The nav links Home and Stories only.
